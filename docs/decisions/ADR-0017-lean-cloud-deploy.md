# ADR-0017: Lean cloud deployment (option B): worker in the API, no Redis, keyless deploys

- **Status:** accepted (Phase 3 M2); not yet applied
- **Date:** 2026-11-22

## Context

ADR-0007's design runs an always-on API (2 vCPU / 2 GiB), an always-on worker pool,
Memorystore Redis and a dedicated Cloud SQL core: roughly $250-290 a month (estimate from
list prices, not a quote). This is a portfolio demo with little traffic. The owner chose a
lean option with a ceiling of about $150/month. Two measurements also matter:
- the API holds about 1.4 GiB for v1.38;
- a background recompute briefly holds a second copy (stale-while-revalidate, ADR-0002),
  so 2 GiB would run out of memory.

## Decision

- **The API runs the event worker in-process** (`WORKER_IN_PROCESS=true`). It pulls the
  Pub/Sub `worker` subscription in a daemon thread and announces new events to SSE
  clients in-process. **Redis is not used in the cloud**: it carried only those
  announcements, because the cloud queue is Pub/Sub. Local Docker keeps Redis and the
  separate worker, so both paths stay tested.
- **One API instance**, 1 vCPU / **4 GiB**, always on (`min = max = 1`). It holds the
  computed release, the only worker, and the SSE clients its worker notifies. Web scales
  0-4.
- **Cloud SQL `db-g1-small`** (shared core), zonal, backups with point-in-time recovery.
- **No VPC**: Cloud SQL is reached through the connector socket, and Redis is gone.
- **Sign-in** (ADR-0016):
  - `AUTH_MODE=required` on API and web;
  - action and session secrets generated by Terraform into Secret Manager;
  - the GitHub OAuth app's ID and secret added by hand;
  - approvers from `var.approvers`.
- **Keyless deploys.** GitHub Actions uses Workload Identity Federation, restricted to
  `main` of this repository, and acts as a deployer account. The deployer may push images,
  update services and jobs, and run the migration job. Each deploy:
  1. builds images tagged with the commit;
  2. runs migrations;
  3. rolls out the poller, API and web;
  4. smoke-tests `/healthz`, `/me` (must say `required`) and the front page.

  Terraform ignores image changes on the services, so a later `apply` does not roll back
  a deploy.
- **Terraform state** lives in a private, versioned GCS bucket (`infra/bootstrap.sh`).
  `make tf-plan` and CI plan offline in a scratch copy with local state.
- **Results files ship in the image** (`docs/results`), so the API's validation labels
  match the repository.

## Alternatives

- **A: as designed** (~$250-290/month): instant pages, separate worker, Redis. Rejected
  on cost for a demo.
- **C: scale to zero** (~$30-60/month): the first visitor after idle waits 40-60 s while the
  release is computed. Rejected: a bad first impression for anyone the link is sent to.
- **Postgres LISTEN/NOTIFY instead of Redis.** Needed only if API and worker are
  separate again. Not needed with the in-process worker.

## Trade-offs

- **No horizontal scaling of the API.** A second instance would run a second worker:
  safe for storage, which is idempotent, but its SSE clients would miss the other
  instance's notices until the 30 s warmer refreshes. Fine at demo traffic. Revisit with
  incremental projection (Phase 3 M4).
- **A crash in the worker thread is logged and retried in-process.** A crash of the API
  instance restarts both.
- The cost figures are estimates. The measured bill replaces them after the first week.
